# 手持弹幕工程代码解析文档

## 一、项目概述

本工程是基于 HarmonyOS ArkTS 的手持弹幕应用，在原有弹幕功能基础上新增了 8 项扩展功能及自由流转功能。采用 `@ComponentV2` + `Navigation` 架构，使用 `NavPathStack` 进行页面路由管理，通过 HarmonyOS 分布式能力实现跨设备自由流转。

## 三、数据模型详解

### 3.1 Settings.ets — 弹幕设置数据模型

**文件路径**: `model/Settings.ets`

```typescript
export enum DisplayArea {
  TOP = 'top',      // 上方显示
  CENTER = 'center', // 居中显示
  BOTTOM = 'bottom'  // 下方显示
}

export enum DisplayMode {
  SLIDE = 'slide',   // 滑动弹幕（从右往左滚动）
  STATIC = 'static'  // 滞留弹幕（静止显示在屏幕上）
}

export class Settings {
  content: string = '';                          // 弹幕文本内容
  fontSize: number = 0;                          // 字体大小（88/168/248）
  fontWeight: FontWeight = FontWeight.Regular;   // 字体粗细
  fontColor: string = '#FFFFFF';                 // 弹幕文字颜色（新增）
  speed: number = 6;                             // 滚动速度 1-12（新增）
  displayArea: DisplayArea = DisplayArea.CENTER;  // 显示区域（新增）
  displayMode: DisplayMode = DisplayMode.SLIDE;   // 显示方式（新增）
  bgColor: string[] = ['#013C9C', '#3066E4', '#43A1F4']; // 背景渐变色（新增）
  themeName: string = '默认蓝';                   // 主题名称（新增）
}
```

**字段说明**:

| 字段 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `content` | string | '' | 弹幕文本内容 |
| `fontSize` | number | 0 | 字体大小，三档：88(小)/168(中)/248(大) |
| `fontWeight` | FontWeight | Regular | 字体粗细：Regular/Medium/Bold |
| `fontColor` | string | '#FFFFFF' | 弹幕文字颜色，支持 HEX 格式 |
| `speed` | number | 6 | 跑马灯滚动步长，1=最慢，12=最快 |
| `displayArea` | DisplayArea | CENTER | 弹幕在屏幕的垂直位置（上方/居中/下方） |
| `displayMode` | DisplayMode | SLIDE | 弹幕显示方式：SLIDE=滑动弹幕，STATIC=滞留弹幕 |
| `bgColor` | string[] | 蓝色渐变 | 背景渐变色数组 [起始色, 中间色, 结束色] |
| `themeName` | string | '默认蓝' | 当前主题名称，用于主题切换联动 |

**构造函数设计**: 新增字段均为可选参数（`fontColor?`, `speed?` 等），通过 `undefined` 判断赋值，**保持向后兼容**，原有的三参数调用方式不受影响。

#### 流转序列化/反序列化方法

自由流转需要在设备间传递 Settings 数据，因此增加了序列化与反序列化能力：

**`toRecord(): SettingsRecord`** — 将 Settings 实例转为可序列化的 `SettingsRecord` 接口对象：
- `fontWeight` 枚举转为 `number` 类型（`FontWeight.Regular/Medium/Bold` → 数值）
- 其余字段保持原类型不变
- 返回的 `SettingsRecord` 可直接通过 `JSON.stringify()` 序列化为字符串

**`static fromRecord(record: SettingsRecord): Settings`** — 从 `SettingsRecord` 反序列化恢复 Settings 实例：
- 通过 `if-else` 判断将数值映射回 `FontWeight` 枚举（ArkTS 不支持计算属性名，因此无法使用映射表）
- 无法匹配时默认使用 `FontWeight.Regular`
- 用于流转恢复时从 JSON 字符串重建 Settings 对象

### 4.3 KeywordFilter.ets — 关键词过滤器

**文件路径**: `utils/KeywordFilter.ets`

**持久化方式**: 使用 `@kit.ArkData` 的 `preferences` API，存储名称 `danmu_keyword`，键名 `filter_keywords`。

**核心逻辑**:
- **添加关键词**: `addKeyword(keyword)` — 去重添加，自动持久化
- **删除关键词**: `removeKeyword(keyword)` — 移除并持久化
- **过滤内容**: `filterContent(content)` — 将匹配到的关键词替换为等长度的 `*` 号
- **检测关键词**: `containsKeyword(content)` — 判断内容是否包含过滤词

**过滤示例**: 关键词列表含"垃圾"，弹幕内容"这个真垃圾" → 过滤后"这个真**"

    │   └── 弹幕预览框（渐变背景 + 跑马灯文字）

        │   └── 统计面板（跳转 StatsPage）

        │   └── 弹幕主题 Select（8套主题）
        └── "显示弹幕" 按钮

#### 核心方法逻辑

**`initManagers(context)`** — 页面加载时异步初始化三个持久化管理器，使用 `Promise.all` 并行初始化，初始化完成后加载已有关键词列表。

**`restoreFromContinue()`** — 自由流转恢复逻辑：
1. 从 `AppStorage` 读取键名 `continueSettings` 的流转数据（JSON 字符串）
2. 若存在流转数据，通过 `JSON.parse()` 反序列化为 Record，再调用 `Settings.fromRecord()` 重建 Settings 对象
3. 清除 `AppStorage` 中的流转数据（避免重复恢复）
4. 延迟 300ms 后自动跳转到弹幕展示页 `Led`，恢复用户流转前的弹幕显示状态
5. 若解析失败，静默清除流转数据，不影响正常使用

**`onSendDanmu()`** — 发送弹幕核心流程：
1. 获取弹幕内容
2. 如有关键词过滤规则，调用 `keywordFilter.filterContent()` 进行替换
3. 封装 `Settings` 对象（包含所有新旧配置项）
4. 将 Settings 序列化为 JSON 字符串存入 `AppStorage`（键名 `continueSettings`），供自由流转 `onSaveData` 读取
5. 异步保存历史记录和统计数据
6. 跳转到弹幕展示页 `Led`

**`handleThemeChange(index)`** — 主题切换时同步更新字体颜色为主题默认色，避免文字与背景不可见。

**`handleSpeedChange(value)`** — 速度值到标签的映射：≤3="慢"，4-8="中"，≥9="快"。

**`applyPreset(template)`** — 一键应用预设模板，将模板内容填入输入框并收起面板。

### 5.2 Led.ets — 弹幕展示页

**文件路径**: `pages/Led.ets`

**装饰器**: `@ComponentV2`

#### 核心功能

- **全屏横屏展示**: `preferredOrientation(window.Orientation.LANDSCAPE)`
- **跑马灯滚动**: `TextOverflow.MARQUEE` + `marqueeOptions({ start: true, step: speed })`
- **文字颜色**: 使用 `settings.fontColor` 替代硬编码白色
- **滚动速度**: 通过 `marqueeOptions.step` 控制步长
- **显示区域**: 通过 `getContentAlign()` 将 `DisplayArea` 映射为 `FlexAlign`
  - TOP → `FlexAlign.Start`（上方）
  - CENTER → `FlexAlign.Center`（居中）
  - BOTTOM → `FlexAlign.End`（下方）
- **背景渐变**: 使用 `settings.bgColor` 数组动态渲染
- **AI 播报**: 右上角菜单按钮，调用 `Speaker.startSpeak()`
- **返回按钮**: 左上角 `chevron_left` 图标

#### 数据接收

```typescript
.onReady((context: NavDestinationContext) => {
  this.settings = context.pathInfo.param as Settings;
})
```

通过 `NavDestination.onReady` 回调接收 Index 页传递的 `Settings` 对象。

### 5.4 StatsPage.ets — 弹幕统计面板页

**文件路径**: `pages/StatsPage.ets`

**装饰器**: `@ComponentV2`

#### 页面结构

```
NavDestination（标题：弹幕统计面板）
└── Column
    ├── 加载中状态
    └── 数据内容
        ├── 统计概览卡片（Row 三列均分）
        │   ├── 总发送量（蓝色大字）
        │   ├── 日均发送（浅蓝大字）
        │   └── 记录天数（绿色大字）
        └── 每日发送统计图表卡片
            ├── 标题 "每日发送统计"
            └── 水平滚动柱状图
                └── Row（底部对齐）
                    └── Column × N（每日一根柱子）
                        ├── 蓝色柱体（高度 = count/maxCount × 160）
                        ├── 数量标签
                        └── 日期标签（MM-DD 格式）
```

#### 柱状图实现原理

采用**纯 ArkUI 布局**实现，无需第三方图表库：
- 每根柱子是一个 `Column` 组件，宽度固定 24px
- 柱子高度按比例计算：`Math.max(4, (count / maxCount) * 160)`
- 最大值柱子占满 160px 高度，其他按比例缩放
- 最小高度 4px 避免为 0 时不可见
- 水平方向使用 `Scroll + Row` 支持横向滚动
- 底部对齐 `alignItems(VerticalAlign.Bottom)`

## 十一、自由流转功能详解

### 11.1 功能概述

自由流转是 HarmonyOS 的分布式核心能力，允许应用在设备间无缝迁移。用户在设备 A 上发送弹幕后，可将应用流转到设备 B，设备 B 自动恢复弹幕显示状态，实现跨设备续播体验。

### 11.2 配置声明

**文件**: `entry/src/main/module.json5`

在 `abilities` 配置中为 `EntryAbility` 添加 `continuable` 属性：

```json
{
  "name": "EntryAbility",
  "exported": true,
  "continuable": true,
  ...
}
```

`"continuable": true` 声明该 Ability 支持跨设备流转，系统会在用户触发流转时调用 Ability 的 `onSaveData` / `onRestoreData` 回调。

### 11.3 数据流转机制

#### 核心常量

```typescript
const CONTINUE_KEY = 'continueSettings';
```

`CONTINUE_KEY` 是流转数据在 `AppStorage` 和 `onSaveData/onRestoreData` 中的统一键名，用于 Ability 层与页面层之间的数据桥接。

#### 数据流转完整流程

```
设备 A（源设备）                          设备 B（目标设备）
──────────────                          ──────────────
1. 用户点击"显示弹幕"
2. onSendDanmu() 封装 Settings
3. Settings.toRecord() → JSON.stringify()
4. 存入 AppStorage[CONTINUE_KEY]
5. 用户触发流转
6. onSaveData() 回调触发
7. 从 AppStorage 取出 JSON 字符串
8. 写入 params[CONTINUE_KEY]
                    ─────────────────→  9. onRestoreData() 回调触发
                                        10. 从 params 读取 JSON 字符串
                                        11. 写入 AppStorage[CONTINUE_KEY]
                                        12. 页面重建，aboutToAppear() 触发
                                        13. restoreFromContinue() 读取 AppStorage
                                        14. JSON.parse() → Settings.fromRecord()
                                        15. 自动跳转 Led 页面，恢复弹幕显示
```

### 11.4 EntryAbility.ets 流转回调

**文件**: `entry/src/main/ets/entryability/EntryAbility.ets`

#### onSaveData(want, params)

在源设备触发流转时由系统调用，负责将当前弹幕设置数据写入 `params` 传递给目标设备：

```typescript
onSaveData(want: Want, params: Record<string, Object>): void {
  const settingsStr = AppStorage.get<string>(CONTINUE_KEY) || '';
  if (settingsStr.length > 0) {
    params[CONTINUE_KEY] = settingsStr;
  }
}
```

- 从 `AppStorage` 读取页面存入的 Settings JSON 字符串
- 仅在数据非空时写入 `params`，避免传递无效数据

#### onRestoreData(want, params)

在目标设备恢复流转时由系统调用，负责从 `params` 读取源设备传递的数据：

```typescript
onRestoreData(want: Want, params: Record<string, Object>): void {
  const settingsStr = params[CONTINUE_KEY] as string;
  if (settingsStr && settingsStr.length > 0) {
    AppStorage.setOrCreate<string>(CONTINUE_KEY, settingsStr);
  }
}
```

- 从 `params` 读取流转数据
- 写入 `AppStorage`，供页面层的 `restoreFromContinue()` 消费

### 11.5 Index.ets 流转恢复

**文件**: `entry/src/main/ets/pages/Index.ets`

#### 数据保存（发送弹幕时）

在 `onSendDanmu()` 中，发送弹幕时将当前 Settings 序列化后存入 AppStorage：

```typescript
AppStorage.setOrCreate<string>(CONTINUE_KEY, JSON.stringify(settings.toRecord()));
```

这确保了流转时 `onSaveData` 能从 AppStorage 中获取到最新的弹幕设置数据。

#### 数据恢复（页面加载时）

`restoreFromContinue()` 在 `aboutToAppear()` 中调用，处理流转恢复逻辑：

```typescript
private restoreFromContinue(): void {
  const settingsStr = AppStorage.get<string>(CONTINUE_KEY);
  if (settingsStr && settingsStr.length > 0) {
    try {
      const record = JSON.parse(settingsStr) as SettingsRecord;
      const settings = Settings.fromRecord(record);
      AppStorage.delete(CONTINUE_KEY);
      setTimeout(() => {
        this.pathInfos.pushPathByName('Led', settings);
      }, 300);
    } catch (e) {
      AppStorage.delete(CONTINUE_KEY);
    }
  }
}
```

**关键设计**:
- 使用 `try-catch` 包裹解析逻辑，解析失败时静默清除数据，不影响正常使用
- 恢复后立即调用 `AppStorage.delete()` 清除流转数据，防止重复恢复
- `setTimeout(300ms)` 延迟跳转，确保页面渲染完成后再导航到 Led 页

### 11.6 Settings.ets 序列化支持

**文件**: `entry/src/main/ets/model/Settings.ets`

#### toRecord()

将 Settings 实例转为显式声明接口 `SettingsRecord`，`fontWeight` 枚举转为 number 以便 JSON 序列化：

```typescript
export interface SettingsRecord {
  content: string;
  fontSize: number;
  fontWeight: number;
  fontColor: string;
  speed: number;
  displayArea: DisplayArea;
  bgColor: string[];
  themeName: string;
}

toRecord(): SettingsRecord {
  const record: SettingsRecord = {
    content: this.content,
    fontSize: this.fontSize,
    fontWeight: this.fontWeight as number,
    fontColor: this.fontColor,
    speed: this.speed,
    displayArea: this.displayArea,
    bgColor: this.bgColor,
    themeName: this.themeName
  };
  return record;
}
```

> 注意：ArkTS 严格模式下对象字面量必须对应显式声明的类或接口（`arkts-no-untyped-obj-literals`），因此使用 `SettingsRecord` 接口而非 `Record<string, Object>`。

#### fromRecord()

从 `SettingsRecord` 反序列化重建 Settings，通过 `if-else` 判断将数值还原为 FontWeight 枚举：

```typescript
static fromRecord(record: SettingsRecord): Settings {
  let fw: FontWeight = FontWeight.Regular;
  if (record.fontWeight === FontWeight.Medium as number) {
    fw = FontWeight.Medium;
  } else if (record.fontWeight === FontWeight.Bold as number) {
    fw = FontWeight.Bold;
  }
  return new Settings(
    record.content,
    record.fontSize,
    fw,
    record.fontColor,
    record.speed,
    record.displayArea,
    record.bgColor,
    record.themeName
  );
}
```

> 注意：ArkTS 不支持计算属性名（`arkts-identifiers-as-prop-names`），因此无法使用 `[key]: value` 形式的映射表，改用 `if-else` 条件判断。

## 十二、弹幕显示方式功能详解

### 12.1 功能概述

弹幕显示方式支持两种模式：

| 模式 | 枚举值 | 效果 | 适用场景 |
|------|--------|------|---------|
| 滑动弹幕 | `DisplayMode.SLIDE` | 文字从右往左滚动（MARQUEE），速度可调 | 长文本、动态滚动场景 |
| 滞留弹幕 | `DisplayMode.STATIC` | 文字静止居中显示，不滚动 | 短文本、标语口号、静态展示 |

两种模式均可配合显示区域（上方/居中/下方）使用，组合出 6 种效果：

| 显示方式 | 显示区域 | 最终效果 |
|---------|---------|---------|
| 滑动弹幕 | 上方 | 顶端滚动 |
| 滑动弹幕 | 居中 | 中部滚动 |
| 滑动弹幕 | 下方 | 底端滚动 |
| 滞留弹幕 | 上方 | 顶端滞留 |
| 滞留弹幕 | 居中 | 中间滞留 |
| 滞留弹幕 | 下方 | 底端滞留 |

### 12.2 DisplayMode 枚举

**文件**: `model/Settings.ets`

```typescript
export enum DisplayMode {
  SLIDE = 'slide',   // 滑动弹幕（从右往左滚动）
  STATIC = 'static'  // 滞留弹幕（静止显示在屏幕上）
}
```

### 12.3 Index.ets 显示方式控件

在显示设置区域中新增"显示方式" Select 控件：

```typescript
Row() {
  Text('显示方式')
    .fontSize(16)
    .fontWeight(FontWeight.Medium)
  Select([
    { value: '滑动弹幕' },
    { value: '滞留弹幕' }
  ])
    .value(this.displayModeIndex === 0 ? '滑动弹幕' : '滞留弹幕')
    .selected(this.displayModeIndex)
    .onSelect((index: number) => {
      this.displayModeIndex = index;
      const modes = [DisplayMode.SLIDE, DisplayMode.STATIC];
      this.displayMode = modes[index];
    })
}
```

### 12.4 Index.ets 预览区条件渲染

预览区根据 `displayMode` 切换渲染方式：

```typescript
Row() {

    Text(this.content)
      .textOverflow({ overflow: TextOverflow.MARQUEE })
      .marqueeOptions({ start: true, step: this.speed })
      .fontSize(this.fontSize / 1.8)
      .fontWeight(this.fontWeight)
      .fontColor(this.fontColor)
  } else {
    Text(this.content)
      .fontSize(this.fontSize / 1.8)
      .fontWeight(this.fontWeight)
      .fontColor(this.fontColor)
      .textAlign(TextAlign.Center)
  }

```

### 12.5 Led.ets 弹幕展示页条件渲染

弹幕展示页同样根据 `displayMode` 区分两种渲染模式：

- **滑动弹幕 (SLIDE)**：使用 `TextOverflow.MARQUEE` + `marqueeOptions({ start: true, step: speed })`，文字从右往左持续滚动
- **滞留弹幕 (STATIC)**：普通 Text + `textAlign(TextAlign.Center)`，文字静止居中显示，不滚动

## 十三、一次开发多端部署功能详解

### 13.1 功能概述

基于 HarmonyOS GridRow/GridCol 栅格布局系统，实现一套代码在手机、平板、2in1 设备上的自适应布局。核心思路是通过断点系统（sm/md/lg）在不同屏幕宽度下呈现不同的布局结构。

### 13.2 断点系统定义

| 断点 | 屏幕宽度 | 典型设备 | 布局策略 |
|------|---------|---------|---------|
| sm | 0-599vp | 手机竖屏 | 单列布局 |
| md | 600-839vp | 手机横屏/小平板 | 双列布局 |
| lg | ≥840vp | 平板/2in1 | 双列加宽布局 |

断点配置统一使用 `BreakpointsReference.WindowSize`（基于窗口尺寸），所有页面保持一致。

### 13.3 Index.ets 栅格布局

**文件**: `pages/Index.ets`

首页采用 `GridRow` + `GridCol` 实现响应式分栏：

- **sm 断点**：单列，预览区在上、设置区在下，与原布局完全一致
- **md/lg 断点**：双列，左侧预览区 + 右侧设置区，充分利用大屏空间

```typescript
GridRow({
  columns: { sm: 1, md: 2, lg: 2 },
  gutter: { x: 16 },
  breakpoints: {
    reference: BreakpointsReference.WindowSize,
    breakpointSystem: [
      { name: 'sm', size: 0 },
      { name: 'md', size: 600 },
      { name: 'lg', size: 840 }
    ]
  },
  onBreakpointChange: (breakpoint: string) => {
    this.currentBreakpoint = breakpoint;
  }
}) {
  GridCol({ span: { sm: 1, md: 1, lg: 1 } }) {
    this.buildPreviewArea()
  }
  GridCol({ span: { sm: 1, md: 1, lg: 1 } }) {
    this.buildSettingsArea()
  }
}
```

预览区高度按断点自适应：sm=199px，md/lg=280px。

### 13.4 Led.ets 自适应弹幕展示

**文件**: `pages/Led.ets`

- **字号自适应**：`getAdaptiveFontSize()` 根据屏幕宽度按比例缩放弹幕字号，以 800vp 为基准，最大放大 2 倍
- **方向适配**：`getPreferredOrientation()` 在 lg 断点（≥840vp）下使用 `UNSPECIFIED`（不锁定方向），允许 2in1 设备自由窗口；手机/平板保持 `LANDSCAPE`（强制横屏）

```typescript
private getAdaptiveFontSize(): number {
  if (this.screenWidth <= 0) {
    return this.settings.fontSize;
  }
  const scale = Math.min(this.screenWidth / 800, 2.0);
  return Math.round(this.settings.fontSize * scale);
}

private getPreferredOrientation(): window.Orientation {
  if (this.screenWidth > 0 && this.screenWidth >= 840) {
    return window.Orientation.UNSPECIFIED;
  }
  return window.Orientation.LANDSCAPE;
}
```

屏幕宽度通过 `onReady` 回调中获取窗口属性计算。
